Abstracción + Herencia:
Instrumento es una clase abstracta. No se puede instanciar directamente. Cada registro crea un objeto concreto: GuitarraAcustica, GuitarraElectrica o GuitarraClasica. Cada una tiene atributos propios (cuerdas, pastilla, nylon).
Factory:
Al registrar, el backend llama a InstrumentoFactory.crearInstrumento(tipo, ...). La fábrica decide qué subclase crear según el tipo elegido. El servicio no usa new GuitarraAcustica() directamente.

State:
Los botones de acción cambian según la disponibilidad del instrumento. Eso es el patrón State en acción: cada estado permite acciones distintas.

Encapsulamiento:
La clase Cliente tiene todos sus atributos privados (nombre, cédula, celular). Los setters validan que los datos no estén vacíos antes de asignarlos. Nadie puede crear un cliente sin datos válidos.
Regla de negocio encapsulada:
El método puedeHacerNuevaReserva() de la clase Cliente controla que no tenga más de 3 reservas activas. La regla vive dentro del objeto, no en el servicio.

Repository:
ClienteRepositorio extiende JpaRepository. Spring genera el SQL automáticamente, sin escribir una línea de SQL.

Builder:
Al crear una reserva, el backend usa ReservaBuilder para construir el objeto paso a paso: .paraCliente() → .delInstrumento() → .desdeFecha() → .hastaFecha() → .build(). El build() valida que todo esté completo.

Strategy:
El descuento aplica un algoritmo diferente según el tipo elegido: sin descuento, VIP (20% off) o temporada (10% off). Cada uno es una clase separada que implementa EstrategiaDescuento.
Observer:
Al crear la reserva, el GestorEventosReserva notifica automáticamente a todos los observadores registrados: ObservadorNotificacionSms (muestra el SMS en consola) y ObservadorRegistroLog (registra la operación).

Adapter:
El SMS se envía a través de AdaptadorSms, que traduce la llamada de nuestra interfaz al sistema legado ServicioSmsLegado.mandarSms().
